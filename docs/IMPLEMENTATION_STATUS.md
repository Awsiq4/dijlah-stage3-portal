## مهام التنفيذ بحسب الأولوية

1. استرجاع المصدر الفعلي والبيانات إذا أمكن؛ وإلا وضع baseline جديد في Git.
2. تعويض localStorage بقاعدة D1 وخدمات API، ثم بناء تسجيل دخول للأدوار وصلاحيات server-side.
3. إعادة استيراد الجدول الـ36، أسماء التدريسيين، روابط القنوات، ملفات المحاضرات الحقيقية، واختبار الأحد.
4. إضافة R2 upload/versioning وPDF viewer موثوق.
5. ربط Telegram jobs / deduplication / opt-in/opt-out.
6. تنفيذ RAG مع مصدر لكل إجابة، واختبارات استرجاع وميزانية وإيقاف.
7. اختبارات خادم ووحدات وتكامل وواجهة، ثم النشر والمراقبة والنسخ الاحتياطي.

## اختبار قبول قبل الإنتاج

- طالب A لا يشوف تبليغات شعبة B إلا العامة؛ مدرس الرياضيات لا يمكنه تعديل مادة أخرى.
- تغيير الشعبة يغيّر الجدول والتبليغات والامتحانات والواجبات بنفس المنطق.
- الأحد يعرض **ثلاث حصص** في البيانات الحقيقية وفي ترتيب الوقت الصحيح.
- التبليغات اسمها الدقيق ومكانها بالأسفل؛ الامتحانات في المزيد.
- الوضع المظلم لا يختفي عند إعادة التحميل ولا يخفي النصوص.
- يظهر «برمجة وتطوير: Aws Faris»، ولا يوجد رابط الجامعة في التذييل.
- كل عمليات الإدارة ترفض طلباً دون session وصلاحية خادم مناسبة.
- استبدال PDF لا يغيّر الرابط العام ويحتفظ بتاريخ الملف.
- أحداث التليجرام تصل مرة واحدة للمشترك المستهدف؛ لا ترسل للملغين الاشتراك.
- AI لا يجيب بدون استشهاد، ويعلن عجزه عند انعدام المراجع.
